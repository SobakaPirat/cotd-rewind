# cotd-recap

Собирает таблицу кубков дня (COTD) игрока с [trackmania.io](https://trackmania.io)
в TSV или CSV.

Скрипт заменил прежний marimo-ноутбук: колонки те же, но сбор устойчивее
(таймауты, ретраи на 429/5xx, остановка по дате, защита от деления на ноль и
от зацикливания пагинации).

## Установка

Проект настроен под [uv](https://docs.astral.sh/uv/): зависимости объявлены в
`pyproject.toml`, версии зафиксированы в `uv.lock`. Нужен Python 3.9+,
зависимость одна — `requests`.

```bash
uv sync            # создаст .venv и поставит requests (+ ruff в dev-группе)
```

Дальше всё запускается через `uv run` — venv активировать вручную не нужно.

<details>
<summary>Без uv (обычный pip)</summary>

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python main.py <tm.io id> -s 2025-01-01
```

</details>

## Запуск

```bash
# вся история игрока в stdout (TSV с заголовком)
uv run main.py <tm.io id>

# только с 1 января 2025, в файл
uv run main.py <tm.io id> -s 2025-01-01 -o cotd.tsv

# CSV, без дней без дивизиона
uv run main.py --player-id <tm.io id> -s 2025-01-01 -f csv --skip-unqualified > cotd.csv

# id из переменной окружения
TMIO_PLAYER_ID=<tm.io id> uv run main.py -s 2026-01-01
```

ID игрока можно передать позиционно, через `--player-id` или через переменную
окружения `TMIO_PLAYER_ID`. Это uuid из URL вида
`https://trackmania.io/#/player/<uuid>`.

## Разработка

```bash
uv run ruff check main.py     # линтер
uv run ruff format main.py    # форматирование
```

## Веб-страница для GitHub Pages

```bash
# один игрок: страница в файл
uv run main.py <tm.io id> --year 2026 --html docs/index.html

# сайт по всем годам из кеша (2020–2026), с переключателем года
uv run main.py --site docs

# только один год (без переключателя на другие)
uv run main.py --site docs --year 2025
```

`--site DIR` собирает статический сайт из кеша (запросов к API не делает) —
по каталогу на год:

```
docs/
├── index.html          # перекидывает на последний год и перечисляет остальные
├── assets/             # общие для всех страниц файлы (кешируются браузером)
│   ├── site.css        # весь CSS сайта — один раз вместо копии в каждой странице
│   └── site.js         # сортировка, вкладки, фильтр, выбор года, подсказки графиков
├── all/                # «всё время»: агрегат по всем годам из кеша
│   ├── index.html
│   ├── walten.html
│   └── …
├── 2026/
│   ├── index.html      # «Таблица игроков» за 2026
│   ├── walten.html     # личная страница: карточки, графики, напарники
│   └── …               # по файлу на каждого игрока с данными за этот год
├── 2025/…
└── 2020/…
```

### Общие файлы (`assets/`)

CSS и клиентский JS вынесены в `docs/assets/`: страницы ссылаются на
`../assets/site.css` и `../assets/site.js`, поэтому браузер скачивает их один раз
на весь сайт, а не тащит по ~19 КБ в каждой из 500+ страниц (средний вес
страницы ~55 КБ вместо ~72 КБ). `site.js` — один файл на все страницы: каждый
блок сам проверяет, есть ли на странице его элементы (таблицы, вкладки, фильтр,
переключатель года, точки графиков), поэтому он безопасен везде и подключается с
`defer`. Стили и скрипты не минифицированы — правки в `report.py` остаются
читаемыми. Внешних CDN нет: всё локальное, сайт работает офлайн.

Одиночная страница `--html` (не через `--site`) по-прежнему собирается
самодостаточной: CSS и скрипты встраиваются прямо в файл, чтобы её можно было
открыть или отправить одним файлом.

В переключателе периода первым пунктом идёт «всё время» (`docs/all/…`), дальше
годы: на странице игрока — только те, где у него есть COTD. На страницах
«всё время» дельт к прошлому году нет (сравнивать не с чем), остальная
статистика считается по всей истории.

Имя файла — slug ника (`WalteN.` → `walten.html`); если ник не латиница или
он занят, добавляется id. В шапке страницы игрока — ссылка-«крошка»
«← Таблица игроков» (на главную года) и переключатель года справа; на самой
главной ссылки нет, там только переключатель года (те годы, где есть данные;
остаёшься на той же странице). Отдельной строки меню над заголовком нет — всё
в шапке, на уровне названия. Переключатель — своё меню на `<details>`
(не нативный `select`), поэтому выглядит одинаково тёмным во всех браузерах;
закрывается по клику вне меню и по `Esc`. Список ников в шапке не держим:
на игрока переходят кликом по нику в таблице — на главной года это вкладки
«Общие показатели» и «Места в раундах», на личной странице — «С кем чаще всего
играл».

Страницы сайта используют общие `assets/site.css` и `assets/site.js`; SVG-графики по-прежнему внутри страниц, внешних CDN нет.
Публикация на GitHub:

1. закоммить папку `docs/` и запушь в репозиторий;
2. Settings → Pages → Source: **Deploy from a branch**, ветка `main`,
   папка `/docs`;
3. через минуту сайт будет на `https://<user>.github.io/<repo>/`.

Что на странице: ник с флагом зоны (как на trackmania.io) и год с двумя счётчиками
в шапке — всего COTD и «сыграно» (старты, где игрок реально ехал раунды; разница —
дни, когда он зашёл в дивизион, но не играл), средние (дивизион,
место, место в раундах, топ по миру в %), медианы (место/раунды/топ) и самый
частый дивизион, первые/вторые/третьи места, топ-8 и топ-32 (у каждой карточки —
доля таких дней от сыгранных COTD), лучшая и худшая карта по топу в мире (имя карты
в этих карточках — ссылка на её таблицу лидеров: `https://trackmania.io/#/leaderboard/<mapUid>`,
если uid карты известен), а также
два графика с линией тренда: места в мире по дням (лог-шкала) и топ по миру по
дням (шкала в процентах). На обоих графиках ниже — лучше. Верх шкалы у обоих
обрезан по 95-му перцентилю: редкие провальные дни не растягивают ось на порядок,
а прижимаются к верхней границе — точное место или процент видно в подсказке при
наведении. Перед
графиками — таблица «С кем чаще всего играл»: остальные игроки из кеша, попавшие в тот же
дивизион в тот же день (см. ниже), а сразу за ней — гистограмма «Дивизионы по
дням»: один столбик на день (COTD — это один день; если за день записей
несколько, например переигровка, берётся лучший дивизион), а высота показывает,
насколько день далёк от 1-го дивизиона — **чем ниже столбик, тем ближе к 1-му
дивизиону** (ниже — сильнее, как на графиках места). Шкала такой гистограммы
обрезана по 95-му перцентилю, иначе один слабый день растягивает ось: редкие
слабые дни прижимаются к верху, точный дивизион виден в подсказке при наведении.
Рядом с метриками — дельта прогресса за год:
вторая половина против первой (зелёная — стало лучше, красная — хуже).

Полезные флаги для страницы:

| флаг | что делает |
| --- | --- |
| `--year YYYY` | ограничить период годом и подписать им страницу |
| `--name NICK` | подставить ник вручную (если профиль недоступен) |
| `--only-cotd` | отбросить записи, в названии которых нет `cotd` |
| `--html PATH` | куда писать страницу (родительские папки создаются сами) |

Если указан `--html` без `--output`, таблица в stdout не печатается.

## Кеш и напарники по дивизиону

Каждый сбор складывается в кеш — `cache/<player_id>.json` (JSON, полная история
игрока). Повторный запуск в пределах `--cache-ttl` часов (по умолчанию 24) не
ходит в API вообще: данные берутся из файла, а `--year`/`--since`/`--until`/
`--skip-unqualified` применяются локально.

```bash
# первый запуск — соберёт и закеширует
uv run main.py <id A> --html docs/index.html

# второй игрок — соберёт его и закеширует
uv run main.py <id B> --html /tmp/b.html

# страница A с таблицей «с кем чаще всего играл» по всем игрокам из кеша
uv run main.py <id A> --year 2026 --partners --html docs/index.html

# принудительно обновить кеш / не трогать кеш вовсе
uv run main.py <id A> --refresh
uv run main.py <id A> --no-cache
```

| флаг | что делает |
| --- | --- |
| `--cache-dir PATH` | папка кеша (по умолчанию `cache`, или `TMIO_CACHE_DIR`) |
| `--cache-ttl HOURS` | сколько часов кеш считается свежим; `0` — не проверять возраст |
| `--refresh` | игнорировать кеш и пересобрать (файл перезапишется) |
| `--refresh-flags` | дозаполнить в кеше недостающие картинки флагов (флаг родительской зоны, если у своей нет файла) |
| `--no-cache` | не читать и не писать кеш |
| `--partners` | добавить на страницу секцию «С кем чаще всего играл» (только вместе с `--html`; старое имя флага `--compare`) |

Играли вместе = **один день и один дивизион**. Дивизионы COTD стартуют в разное
время, поэтому совпадение дня без совпадения дивизиона за совместный заезд не
считается (дни без дивизиона отбрасываются). Считается по кешам всех игроков,
которые есть в `--cache-dir`, на тех же фильтрах, что и текущая страница.
Колонки: количество общих COTD, доля от моих COTD с дивизионом, средняя разница
мест в мире в общих заездах.

### Сравнение с прошлым годом

Рядом со средними и медианами — дельта к предыдущему году: страница 2025
сравнивается с 2024, страница 2026 — с 2025. Сравниваются все показатели: дивизион,
место, место в раундах, средний и медианный топ по миру, а также самый частый
дивизион. `−1` зелёным — стало лучше (меньше), `+2,3` красным — хуже, `±0` серым;
у показателей топа разница в процентных пунктах (`+5,4` при `12,65 %`). С каким
годом идёт сравнение, видно в подсказке при наведении (`2024: 3,1 → сейчас: 2,9`)
и в пояснении под блоком средних значений.

Сравнение включается, только если в обоих годах хотя бы 5 стартов; если
предыдущего года нет (или в нём меньше 5 COTD), вместо дельт выводится
пояснение «Сравнить не с чем».

Сортировка таблицы на главной (`index.html`):
- по умолчанию — по среднему месту (от меньшего к большему);
- флаг `--sort KEY` задаёт колонку, `--sort-desc` — направление по убыванию.
  Ключи: `cotd`, `avg_rank`, `avg_top`, `avg_div_rank`, `mode_div`, `median_rank`,
  `median_div_rank`, `median_top`. Пример «от меньшего к большему по количеству
  COTD»: `--sort cotd`. Для `mode_div` ключ составной: сначала дивизион, при
  равенстве — больше повторов выше (`1 (×98)` раньше, чем `1 (×15)`);
- на странице таблица сортируется **кликом по заголовку** (повторный клик меняет
  направление, стрелка показывает текущую сортировку) — работает офлайн, без
  внешних скриптов. Так же сортируется таблица напарников.

Слева в каждой таблице — колонка «№»: номер строки в текущей сортировке. Она не
сортируемая (клик по ней ничего не делает) и пересчитывается скриптом после
сортировки и после фильтра: первый видимый игрок всегда №1, скрытые строки номер
не занимают.

На главной три таблицы, переключаются кнопками над ними (каждая сортируется
независимо кликом по заголовку):
- **Средние показатели** — средний дивизион, среднее место, средний топ по миру,
  среднее место в раундах;
- **Медианные показатели** — самый частый дивизион, место, раунды и топ по миру
  (медианы);
- **Места в раундах** — сколько раз игрок занимал 1-е, 2-е и 3-е место в раундах и
  сколько раз попадал в топ-3, топ-8 и топ-32; по умолчанию отсортировано по первым
  местам, в подсказке у числа — доля от сыгранных COTD. Сортируется кликом по
  заголовку так же, как первая.

Справа от вкладок — маленький фильтр «от 10 COTD» (по умолчанию 10): он прячет
игроков с меньшим числом стартов во всех трёх таблицах. В списке — 10, 25, 50,
100 и «все». Фильтр клиентский, данные в HTML остаются полными.

Кеш содержит только уже посчитанные поля таблицы, никаких токенов и приватных
данных. Кроме строк COTD там лежат `zone`/`flag`/`flag_data`: зона игрока, имя
файла её флага на trackmania.io (`/img/flags/<flag>.jpg`) и сама картинка в виде
data URI — поэтому страницы собираются офлайн, без внешних CDN.

Ещё в кеше лежит `map_uids` — словарь `{"YYYY-MM-DD": "mapUid"}` для карт COTD этого
игрока, и `map_uid` в каждой строке. По ним имя карты в карточках «Лучшая карта» и
«Худшая карта» становится ссылкой на таблицу лидеров trackmania.io
(`#/leaderboard/<mapUid>`). Если uid нет (старый кеш), карточка показывает просто
имя карты.

При генерации сайта (`--site`) флаги выкладываются отдельными файлами в
`<site>/flags/<flag>.jpg`, а страницы ссылаются на `../flags/…`: так один и тот же
флаг не дублируется в каждой ячейке, и страницы остаются лёгкими. Одиночный
`--html` по-прежнему встраивает флаг в файл как data URI.

Картинка есть не у каждой зоны: у города Мюнхен `flag` = `Munchen`, а файла
`Munchen.jpg` на trackmania.io нет — сайт показывает флаг Баварии. Поэтому в кеш
пишется не только имя файла первой зоны, но и вся цепочка `parent`-зон, и при
скачивании берётся первый доступный файл (город → регион → страна → континент).
Кеши, собранные до этой логики, дозаполняются командой:

```bash
# добрать недостающие картинки флагов в кеше
uv run main.py --refresh-flags

# то же самое и сразу пересборка сайта
uv run main.py --refresh-flags --site docs
```

Если картинки в кеше нет, но файл `<site>/flags/<flag>.jpg` остался с прошлой
генерации, он переиспользуется — сама генерация сайта в сеть не ходит.

## Колонки

| колонка | смысл |
| --- | --- |
| `map_date` | дата COTD, `YYYY-MM-DD` |
| `map_name` | имя карты без `$fff`/`$i`-разметки |
| `map_uid` | uid карты в trackmania.io (для ссылки на её таблицу лидеров) |
| `div` | дивизион игрока (`0` — не квалифицировался) |
| `div_rank` | место внутри дивизиона (пусто, если места нет) |
| `rank` | общее место |
| `top` | доля игроков впереди: `rank / totalplayers` (0..1), 6 знаков; пусто, если данных нет |
| `total_players` | всего игроков в этот день |

Имена полей в API нестабильны: список записей приходит в `cotds` **или** `cups`,
а внутри записи встречаются `timestamp`/`date`, `div`/`division`,
`rank`/`position`, `mapname`/`map.name` и т.п. Скрипт пробует кандидатов по
порядку (см. `DATE_FIELDS`, `NAME_FIELDS`, `DIV_FIELDS`, `RANK_FIELDS`,
`PLAYERS_FIELDS` в `main.py`), так что оба варианта разбираются одинаково.

## Полезные флаги

| флаг | что делает |
| --- | --- |
| `-s/--since`, `-u/--until` | границы периода `YYYY-MM-DD`, включительно |

| `-o/--output` | писать в файл вместо stdout |

| `--max-pages` | предохранитель от бесконечной пагинации (по умолчанию `200`) |
| `--timeout` | таймаут запроса, сек (по умолчанию `30`) |
| `--base-url` | подменить адрес API (по умолчанию `https://trackmania.io/api`, или `TMIO_API_BASE`) |
| `--dump-json PATH` | сохранить сырые ответы API (JSON Lines) — для разбора структуры |
| `--html PATH` | собрать страницу со статистикой (например `docs/index.html`) |
| `--year YYYY` | ограничить период одним годом и подписать им страницу |
| `--name NICK` | ник для заголовка страницы (иначе берётся из профиля) |
| `--only-cotd` | оставить только записи, в названии которых есть `cotd` |
| `--refresh-flags` | дозаполнить в кеше картинки флагов (с `--site` — заодно пересобрать сайт) |
| `-v/--verbose` | DEBUG-лог в stderr (в т.ч. ключи и пример первой записи) |

## User-Agent

trackmania.io не требует токенов, но просит вежливый `User-Agent` с контактом
(например, ник в Discord) — чтобы было с кем связаться при проблемах. Личные
данные в репозиторий не кладём, поэтому контакт задаётся одним из способов:

```bash
# 1) переменная окружения — приоритет выше
TMIO_USER_AGENT="discord: ник | cotd-recap" uv run main.py <id>

# 2) локальный файл (в .gitignore, в репозиторий не попадёт)
cp local_settings.example.py local_settings.py
$EDITOR local_settings.py     # USER_AGENT = "discord: ник | cotd-recap"
uv run main.py <id>
```

Если не задано ни то, ни другое, используется нейтральный
`cotd-recap (trackmania.io COTD stats)`. Сам `local_settings.py` добавлен в
`.gitignore`, а в репозитории лежит только образец `local_settings.example.py`.

## Если таблица пустая

Скрипт сам объясняет причину — смотри последние строки в stderr:

```
WARNING: ничего не собрано — страниц: 1, записей из API: 0
WARNING: API не отдал ни одной записи: скорее всего неверный id игрока ...
```

Расшифровка сводки:

| в сводке | что значит | что делать |
| --- | --- | --- |
| `записей из API: 0` | страница пустая или id неверный | нужен **uuid** из `https://trackmania.io/#/player/<uuid>`, а не ник |
| `отсечено по --since: N` | данные есть, но старше границы | отодвинуть `-s` назад или убрать его |
| `без дивизиона: N` | стоял `--skip-unqualified`, а игрок не квалифицировался | убрать флаг |
| `без распознаваемой даты: N` | в ответе нет/иной формат даты | прогнать с `-v` (покажет ключи записи) и `--dump-json`, прислать дамп |

Дополнительно: `-v` показывает `ключи первой записи` и `пример записи`, а
`--dump-json /tmp/raw.jsonl` сохраняет сырые ответы страниц
(`{"page": 0, "payload": {...}}` на строку).

## Коды возврата

| код | значение |
| --- | --- |
| `0` | успех (в том числе если под фильтр не попало ни одной карты) |
| `1` | ошибка API/сети/записи файла |
| `2` | неверные аргументы (нет id игрока, `--since` позже `--until`) |
| `130` | прервано Ctrl+C |

Логи идут в stderr, поэтому `uv run main.py <id> > cotd.tsv` даёт чистый TSV.
